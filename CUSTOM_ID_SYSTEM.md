# Custom ID System Documentation
## Bed Texture E-commerce Platform

### Overview
The database now uses a custom ID system with meaningful prefixes instead of auto-incrementing integers. This provides better readability, easier debugging, and more professional-looking identifiers.

### ID Format
All IDs follow the format: `PREFIX + 10-digit zero-padded number`

Example: `USER0000000001`, `PROD0000000123`, `ORDER0000005678`

### Supported Prefixes

| Prefix | Description | Example |
|--------|-------------|----------|
| USER | User accounts | USER0000000001 |

### Transaction Number Table (transno)

The `transno` table manages the counter for each prefix:

```sql
CREATE TABLE transno (
    prefix VARCHAR(20) PRIMARY KEY,
    count BIGINT UNSIGNED NOT NULL DEFAULT 0,
    details TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

#### Fields:
- **prefix**: The ID prefix (e.g., 'USER', 'PROD')
- **count**: Current counter value
- **details**: Description of what this prefix is used for
- **created_at**: When this prefix was first created
- **updated_at**: Last time the counter was incremented

### ID Generation Function

The `get_next_id()` function handles automatic ID generation:

```sql
CREATE FUNCTION get_next_id(prefix_name VARCHAR(20)) 
RETURNS VARCHAR(50)
READS SQL DATA
DETERMINISTIC
BEGIN
    DECLARE next_count BIGINT;
    DECLARE new_id VARCHAR(50);
    
    -- Get and increment the count atomically
    UPDATE transno SET count = count + 1 WHERE prefix = prefix_name;
    
    -- Get the new count
    SELECT count INTO next_count FROM transno WHERE prefix = prefix_name;
    
    -- Format the ID with leading zeros (10 digits)
    SET new_id = CONCAT(prefix_name, LPAD(next_count, 10, '0'));
    
    RETURN new_id;
END
```

### Usage in Tables

Tables now use VARCHAR(50) for ID fields with default values:

```sql
CREATE TABLE users (
    id VARCHAR(50) PRIMARY KEY DEFAULT (get_next_id('USER')),
    email VARCHAR(255) NOT NULL UNIQUE,
    -- other fields...
);

CREATE TABLE products (
    id VARCHAR(50) PRIMARY KEY DEFAULT (get_next_id('PROD')),
    sku VARCHAR(100) NOT NULL UNIQUE,
    -- other fields...
);
```

### Database Queries

#### Common Query Patterns

**1. Finding Records by ID:**
```sql
-- Find user by ID
SELECT * FROM users WHERE id = 'USER0000000001';

-- Find product by ID
SELECT * FROM products WHERE id = 'PROD0000000123';
```

**2. Joining Tables:**
```sql
-- Get orders with user information
SELECT 
    o.id as order_id,
    o.order_number,
    u.id as user_id,
    u.email,
    u.first_name,
    u.last_name
FROM orders o
JOIN users u ON o.user_id = u.id
WHERE o.status = 'pending';
```

**3. Filtering by Prefix:**
```sql
-- Get all user IDs
SELECT id FROM users WHERE id LIKE 'USER%';

-- Get all product IDs
SELECT id FROM products WHERE id LIKE 'PROD%';

-- Extract numeric part
SELECT 
    id,
    CAST(SUBSTRING(id, 5) AS UNSIGNED) as numeric_id
FROM users
ORDER BY numeric_id;
```

```sql
-- View all prefix counters
SELECT 
    prefix,
    count,
    details,
    updated_at
FROM transno
ORDER BY prefix;
```

#### Reset Counter (if needed)
```sql
-- Reset a specific counter (use with caution!)
UPDATE transno SET count = 0 WHERE prefix = 'USER';

-- Set counter to specific value
UPDATE transno SET count = 1000 WHERE prefix = 'PROD';
```

### Performance Considerations

#### Indexing
- VARCHAR primary keys are slightly slower than BIGINT
- All foreign key columns are properly indexed
- Consider composite indexes for frequently queried combinations

```sql
-- Example composite indexes
CREATE INDEX idx_orders_user_status ON orders(user_id, status);
CREATE INDEX idx_products_category_status ON products(category_id, status);
```

#### Query Optimization
```sql
-- Use exact matches instead of LIKE when possible
-- GOOD:
SELECT * FROM users WHERE id = 'USER0000000001';

-- AVOID (unless necessary):
SELECT * FROM users WHERE id LIKE 'USER%';
```

### Migration from Auto-Increment IDs

If migrating from existing auto-increment system:

```sql
-- Example migration script
-- 1. Add new ID column
ALTER TABLE users ADD COLUMN new_id VARCHAR(50);

-- 2. Generate new IDs for existing records
UPDATE users SET new_id = CONCAT('USER', LPAD(id, 10, '0'));

-- 3. Update transno counter
UPDATE transno SET count = (SELECT MAX(id) FROM users) WHERE prefix = 'USER';

-- 4. Update foreign key references
-- (This requires careful planning and testing)

-- 5. Drop old ID column and rename new_id to id
-- (After all references are updated)
```

### Best Practices

#### Application Development
1. **Always use parameterized queries** to prevent SQL injection
2. **Validate ID format** in application code:
   ```javascript
   const isValidUserId = (id) => /^USER\d{10}$/.test(id);
   const isValidProductId = (id) => /^PROD\d{10}$/.test(id);
   ```
3. **Use constants for prefixes**:
   ```javascript
   const ID_PREFIXES = {
       USER: 'USER',
       PRODUCT: 'PROD',
       ORDER: 'ORDER',
       // ...
   };
   ```

#### Database Operations
1. **Use transactions** when creating related records
2. **Monitor transno table** for unusual counter jumps
3. **Backup transno table** regularly
4. **Test ID generation** under concurrent load

#### Security
1. **Don't expose internal IDs** in URLs if not necessary
2. **Use UUIDs for public-facing tokens** (like password reset tokens)
3. **Validate ID ownership** before allowing operations

### Troubleshooting

#### Common Issues

**1. Duplicate Key Errors:**
```sql
-- Check for duplicate IDs
SELECT id, COUNT(*) 
FROM users 
GROUP BY id 
HAVING COUNT(*) > 1;
```

**2. Counter Synchronization:**
```sql
-- Sync counter with actual data
UPDATE transno 
SET count = (
    SELECT COALESCE(MAX(CAST(SUBSTRING(id, 5) AS UNSIGNED)), 0)
    FROM users
)
WHERE prefix = 'USER';
```

**3. Function Not Working:**
```sql
-- Check if function exists
SHOW FUNCTION STATUS WHERE Name = 'get_next_id';

-- Test function manually
SELECT get_next_id('TEST') as test_id;
```

### Testing

#### Unit Tests

```javascript
describe('ID Generation', () => {
    test('should generate valid user ID', async () => {
        const userId = await generateId('USER');

    });
    
    test('should generate sequential IDs', async () => {
```

#### Load Testing
```javascript
// Test concurrent ID generation
const testConcurrentGeneration = async () => {
    const promises = Array(100).fill().map(() => generateId('USER'));
    const ids = await Promise.all(promises);
```
